# 獎金發放規則規格表（2026-08-10 定版）

本文件為後續調整前端 UI 與後端程式邏輯的**唯一依據**。
每項標註「現況」＝目前程式已實作；「調整」＝本次確認要改的項目；「待議」＝尚未定案。

---

## 0. 名詞與共同前提

| 名詞 | 定義 |
|---|---|
| 資料月 | 營收/訂單實際發生的月份（例：2026-07） |
| 發放月 | 實際撥款的月份，資料月的隔月 10 日（例：2026-08-10） |
| 費率版本 | 一律取**資料月當時生效版本**（`effective_from <= 資料月`），append-only |
| 入住營收 | 訂單 `final_price` 全額（**含所有加購**）按住宿夜次攤提到各日 → 與業主月結報告完全一致 |
| 分潤基準金額 | `final_price` 扣除加購後的金額，扣除範圍依各獎金線口徑（見 §5） |
| 免抽成來源 | `owner_settlement_pricing_rules.exempt_order_sources` ＋ `orders.owner_direct`，**與 PMS 業主月結平台抽成費同一份設定** |
| 合作期間旗標 | `counts_team_bonus`（團隊獎金線）／`counts_closer_commission`（成交大師線），兩者**完全獨立可任意組合** |
| 在職檢查（定版） | **資料月內有在職即發，並按在職天數比例計算**（例：8/14 離職 → 14/31；8/16 到職 → 16/31）。全線統一此口徑 |

### 合作期間旗標舉例
雲岫 7/1–7/26：`counts_closer_commission = 開`、`counts_team_bonus = 關`
→ 7 月訂單的成交組分潤／影音分潤**照發**；7 月營收**完全不計入**任何團隊獎金。
7/27 起兩者皆開 → 兩線都計。

### 業主自帶口徑（payout_basis）— 已定案：永久廢除
不再有雙軌概念，一律以「含業主自帶」單軌計算。
**待辦**：移除 `accommodation_partnership_periods.payout_basis` 與 `teamcommission_bonus_snapshots` 的雙軌欄位、清除 `use-owner-direct-basis` 等殘留程式與 UI。

## 1. 團隊獎金

### 1-1 AM 績效獎金
| 面向 | 內容 |
|---|---|
| 領取資格 | 有 `am` 角色綁定 ＋ 館別在其所轄範圍 ＋ **在職檢查**（資料月內在職即發，按在職天數比例） |
| 計算基礎 | 入住營收（夜次攤提，含業主自帶），與業主月結一致 |
| Gate | ① 館別合作期間起始日之後（`counts_team_bonus`）② AM 場域總覽「負責 AM」＝本人 ③ 排除 hold／取消單 ④ 排除零價訂單 ⑤ 共用訂單來源白名單 |
| 隱含 Gate | 幣別換算台幣；未設合作期間的館別完全不計 |
| 增值服務 | 只扣館別 `commission_excluded_addon_ids/types`（與業主月結一致） |
| 費率版本 | 資料月版本 |
| 調整項 | 新增「在職檢查」 |

### 1-2 AM 場域獎金
| 面向 | 內容 |
|---|---|

### 1-3 AM 總管獎金
| 面向 | 內容 |
|---|---|

| 計算基礎 | **所轄館別營收加總**（現階段僅 1 位＝全公司所有有效合作館別） |

### 1-4 成交組績效獎金

### 1-5 成交組主管管理獎金
| 面向 | 內容 |

| 計算基礎 | 所轄館別營收加總（現階段僅 1 位＝全公司） |
| 多位情境（定案） | 同 AM 總管：2 位以上時各自依所轄館別營收計算，需新增「所轄館別」設定 |

### 1-6 網紅營銷專利獎金（抽成）

## 2. 成交大師獎金（增值服務須全額扣除）

### 2-1 成交組分潤（成交組訂房佣金）
| 面向 | 內容 |
|---|---|
| 領取資格 | 依訂單歸屬的成交人，從成交組成員篩選 |
| 合作期間旗標 | `counts_closer_commission`（與團隊獎金旗標獨立） |
| 免抽成來源 | 排除 `owner_direct` ＋ `exempt_order_sources`；**與 PMS 業主月結平台抽成費為同一份設定同一版本規則**（UI 說明文字必須明寫此點） |
| 其他 Gate | 排除 hold／取消／`final_price <= 0`／非台幣 |
| 採計時點 | **下訂日口徑**（`order_date`） |
| 分潤基準 | `final_price` − **全部加購** |

### 2-2 成交組多扣回補（調整項）
| 面向 | 內容 |
|---|---|
| 現況 | `create-commission-adjustments` 每月 10 日執行，只核對「上個月退房」的快照（一次性） |
| **調整** | 改為**每月持續核對**：每期重算所有歷史快照，發放後才變動的訂單也能在下一期自動產生調整項 |
| 已發放快照 | **不修改原快照**，一律以調整項於下期加減 |
| 情境 | A 金額變動（重算差額）／B 訂單取消（全額負數扣回）／C 取消後復活（補回） |
| 手動按鈕 | 發放管理的「手動重新計算」呼叫的是 `create-commission-snapshots`（resync），非 adjustments；兩者職責需在 UI 上區分說明 |

### 2-3 影音組分潤（影音組訂房佣金）
| 面向 | 內容 |
|---|---|
| 規則 | **與成交組分潤完全一致**（資格判定方式、gate、基準、口徑） |
| 唯一差異 | 需額外核對「訂單 ↔ 廣告編號 ↔ 影音組人員」的對應（`ad_video_creator_rules`） |
| 費率 | 影音費率獨立版本 |

## 3. 星探獎金

### 3-1 星探稀有度獎金
| 面向 | 內容 |
|---|---|
| 資格 | `kol_profiles`：`is_error = false`、`kpi_qualified = true`、`invited_at` 非空、`check_in_date` 落在期別區間 |
| 金額 | `kol_rarity_settings` 各稀有度固定金額（取最新版本） |
| 正職特例 | 邀約 `check_in_date` 年月 ≥ `fulltime_start_yearmonth` 者，該期別內 SR/SSR/UR 依建立時間排序，**前 30 筆不計獎、第 31 筆起才給**；兼職／外部星探每筆都計 |
| **調整** | 新增**在職檢查** |
| 明確不套用 | 合作期間 gate、訂單是否實際成立（維持現況不檢查） |

### 3-2 星探兼職 — 個人邀約目標獎金（星探底薪）
| 面向 | 內容 |
|---|---|
| 資格 | **僅兼職**；正職一律 0 |
| 期別 | 僅每月 **10 號期**發放，25 號期不計 |
| 達標判定 | 以 `kpi_month = 上月` 的邀約，對 `scout_team_targets` **每一個館別都需 ≥ `personal_min`**，全部達標才發（一館未達即不發） |
| 金額 | `scout_salary_settings.base_salary` 固定金額 |
| 決議 | **完全維持現況** |

### 3-3 星探正職 + 兼職 — 團隊邀約目標獎金
| 面向 | 內容 |
|---|---|
| 發放對象 | `team_member_profiles.is_scout_team_member = true` 的成員（正職＋兼職同額）；外部星探（`false`）強制 0 |
| 達標判定 | `kpi_month = 上月`；每館別「兼職全部邀約 ＋ 正職僅 SR/SSR/UR」**累加** ≥ `target_count`；所有館別皆達標才成立 |
| 金額 | `scout_salary_settings.team_bonus` 固定金額，全體同額 |
| 期別 | 僅 10 號期 |
| **調整 1** | 新增**在職檢查** |
| **調整 2** | **新進成員按到職日按比例**發放 |
| **調整 3** | 目標館別需在合作期間內才列入（未簽約／已終止館別不列入目標） |

### 3-4 KOL 訂單星探分潤（使用 KOL 折扣代碼）
| 面向 | 內容 |
|---|---|
| 現況 | 以星探歷史 `kpi_qualified` 累積件數決定 `scout_tier_settings` 階梯費率 × 分潤基準 |
| 訂單比對 | 訂單 `discount_code` ∈ 該星探名下 KOL 的 `cid_code`；`order_date` 落在期別區間 |
| 現有排除 | 取消單、非台幣、`isExempt`（owner_direct／免抽成來源）；分潤基準扣**全部加購** |
| **調整** | 新增：排除 hold 保留單、排除零價訂單、套用合作期間 gate |

### 3-5 星探訂單分潤（使用星探專屬折扣代碼）
| 面向 | 內容 |
|---|---|
| 來源 | `scout_discount_codes`（`is_active = true`），依 `discount_code` 比對訂單 |
| 期間 | `order_date` 落在期別區間（台北時區半開區間） |
| 分潤腿 | `commission_type = 'partner'` → 同時發 scout（`scout_rate`）＋ closer（`closer_rate`）；否則僅發 scout |
| 現有排除 | 取消單、非台幣、`isExempt`；基準扣**全部加購** |
| 快照 | 寫入 `scout_discount_code_payouts`，`payout_status = 'paid'` 不再更新 |
| 疊加關係 | 與 KOL 分潤、成交組抽成**三者疊加共存**，不互斥、不擇高 |
| 在職檢查 | **不需要**，離職仍發（訂單已成立） |
| **調整** | 新增：排除 hold、排除零價、套用合作期間 gate |

## 6. 本次確認的調整清單（實作待辦）

### 後端邏輯
1. AM 績效：新增在職檢查
2. 成交組績效：離職者改**按日比例**分配（取代目前均分不計比例）

4. 星探稀有度：新增在職檢查

7. 星探專屬折扣碼分潤：新增排除 hold、零價、合作期間 gate（不加在職檢查）

### 前端 UI
1. 場域成交人（Closer）卡片：明確標示合作期間起始日為 AM 績效／各團隊獎金的採計起算基準

3. 共用訂單來源卡片：明示影響 AM 績效、AM 總管、成交組績效、成交組主管

5. 成交組分潤說明文字：明寫「免抽成來源與業主月結平台抽成費設定完全一致」
6. TeamHome／發放管理：每項獎金加註「是否排除增值服務／排除範圍」
7. 發放管理：區分「手動重新計算（resync 未發放快照）」與「每月調整項（已發放快照補差）」兩者職責
8. HQ 整合頁：AM 場域固定金額、網紅專利接收人綁定，限 Ken／貝瑞層級可編輯
